## 模块职责与实体

本模块将权限拆为文件系统、网络和审批三部分。`Permissions` 是当前权限快照；`FileSystemSandboxPolicy` 保存策略种类与路径条目，`NetworkSandboxPolicy` 单独约束出站访问。`ExecApprovalRequestEvent`、补丁审批和 MCP `ElicitationRequest` 描述请求；`GuardianAssessmentEvent` 保存审查生命周期，而不是直接授予权限。

## 主要规则

`SRC-0002/rule/file-system-access-mode-conflict-precedence` 定义路径冲突：先选更具体的路径；同样具体时 **None > Write > Read**。None 是拒绝，不是“未配置”。`SRC-0002/rule/resolve-access-precedence` 在无匹配条目时也返回 None。默认文件系统为 Restricted 加根目录 Read，默认网络 Restricted。

特殊路径包括 cwd、项目根、临时目录和根目录。`TMPDIR` 必须非空且可解析为绝对路径；`/tmp` 需存在为目录。规范化尝试已有祖先，失败则保留输入。`.git` 指针文件解析相对其父目录，目标不存在或内容无效则不采用；符号链接保护路径有时必须保留原始表示，不能一律 canonicalize 后丢弃。

## 主要流程

`SRC-0002/uc.sub/resolve-filesystem-access`：解析特殊路径 → 筛选覆盖目标的条目 → 比较具体程度与访问优先级 → 得到读写能力。追加 readable/writable 根只补尚未有效允许的路径，避免重复。

`SRC-0002/uc.sub/project-to-legacy-sandbox-policy` 将拆分策略投影到旧 `SandboxPolicy`。全盘写且网络开放可归为 `DangerFullAccess`；全盘写但网络受限对应 `ExternalSandbox`。若 workspace 根不可写，却要求其他可写根，旧表示无法表达，会报错。往返投影语义不等价时，`SRC-0002/rule/needs-direct-runtime-enforcement-criterion` 要求直接执行新策略，不能假装转换成功。

审批可选项按上下文生成：网络请求可有单次批准、会话批准、允许主机的策略修订与 Abort；追加权限请求仅有 Approved/Abort；一般命令请求可另含前缀修订。显式提供的 `available_decisions` 优先，缺失才用兼容逻辑。审批 ID 优先 `approval_id`，否则 `call_id`。

## 边界与追溯

`SRC-0002/rule/guardian-event-omits-fields-while-in-progress`：进行中的审查不填写风险、理由或决策来源，避免把未完成判断当结果。Unknown 特殊路径允许旧运行时警告并忽略；这不是自动授权。是否全盘可读还要排除显式拒绝，是否全盘可写要检查收窄条目。默认元数据保护与显式规则的优先关系、符号链接和 legacy 转换需一起验证。
