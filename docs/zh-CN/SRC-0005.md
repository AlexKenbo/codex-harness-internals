## 模块职责与实体

`StateRuntime` 管理独立的 state/logs 数据库。状态库保存 Thread、动态工具、父子线程边、批处理 `AgentJob`/`AgentJobItem`、回填状态、远程控制注册及两阶段记忆任务；日志库按线程或进程分区保存诊断信息。记忆的 `Job` 通过租约、所有权令牌和水位协调并发工作。

## 关键预算与规则

`SRC-0005/rule/log-partition-size-limit` 和 `log-partition-row-limit` 将每分区限制为 **10 MiB、1,000 行**，启动清理删除 **10 天**前日志；单条超过容量也会被删除。SQLite 使用 WAL、NORMAL 同步、**5 秒** busy timeout，每池最多 **5 个连接**。

线程列表排除没有首条用户消息的记录；游标按时间和 ID 倒序，取 page_size+1 判断下一页。热时间桶内 updated_at 递增毫秒避免分页重复，但相差至少 1 秒的历史时间可原样接受，不能理解成跨所有历史导入绝对单调。普通 upsert 保留既有 memory_mode，显式 rollout 元数据更新则可以改变它。

## 主要流程

`SRC-0005/uc.user/run-batch-agent-job` 创建作业和条目，条目 Pending → Running 时增加 attempt_count；只有指定线程报告且条目仍 Running 才能原子写入结果并完成。作业可取消，条目状态没有 Cancelled；迟到或冒名报告不生效。

`SRC-0005/uc.user/run-thread-memory-extraction` 选取满足年龄、空闲时间和 enabled 条件的线程，检查水位、全局并发数及租约，再领取 stage-1。重试预算默认 **3**，新输入水位可以重新提供预算。完成时必须匹配 running 状态与 ownership_token，旧 worker 不能覆盖新 owner。

`SRC-0005/uc.user/consolidate-global-memory` 使用唯一全局 phase-2 作业。输入必须非空、可用且未过期，优先使用频次和新鲜度；成功后原子重写已选基线，水位只向前推进。标记 polluted 会将线程排除，并在其曾进入基线时触发重新汇总；清理过期 stage-1 不删除当前基线。

## 边界与追溯

回填采用 id=1 单例及租约，Complete 后不能再 claim。父子边每个 child 只有一个 parent，后代按广度优先；同一路径有多个匹配会报错。远程注册以 websocket_url、account_id、client_name 联合识别。数据库版本切换会清理匹配旧版本命名的文件及 sidecar；自动 vacuum 是 best-effort，不能把这段描述当作手动删除数据库的操作建议。`SRC-0005/rule/clear-memory-data-scope` 只清 stage-1 和两类记忆任务，不影响其他任务类型。
