## 模块职责与实体

本模块连接 rollout 事件、内存模型和数据库行。`ThreadMetadata` 是统一线程摘要，`ThreadRow` 与各类 Job/Stage1/Backfill 行负责存取转换；`ThreadsPage`、`Anchor`、`SortKey` 支持游标分页。日志侧从 tracing span 提取线程上下文，经队列批量落库，再由 logs_client 过滤和展示。

## 关键规则

`SRC-0006/rule/log-queue-capacity` 将日志队列限制为 **512 条命令**，try_send 满时丢弃新消息，不阻塞业务。`SRC-0006/rule/log-batch-flush` 在 **128 条记录**、**2 秒**定时器或显式 Flush 时写库。每进程有 `pid:<pid>:<uuid_v4>`，区分共享数据库的进程。

日志客户端默认回填 **200 行**、每 **500 ms** 轮询；backfill=0 跳过历史。时间筛选支持 Unix 秒或 RFC3339，空模块/文件/线程过滤项被忽略。state/logs 迁移版本为 **5/2**；运行时忽略未知的已应用迁移，但仍核验已知迁移校验和。

## 主要流程

`SRC-0006/uc.sub/extract-thread-metadata-from-rollout` 逐项更新元数据：SessionMeta 只有 ID 匹配才采用，防止 fork 混入父会话资料；TurnContext 仅在 cwd 空时补 cwd，但始终更新模型和策略。首条真实用户消息只能来自 EventMsg::UserMessage，不能把系统生成的 user-role ResponseItem 当作标题。首条内容仅写一次，重命名只更新 title；纯图片消息首条预览为 `[Image]`，不据此设置标题。token 用量下限为 0。

`SRC-0006/uc.sub/persist-tracing-event-to-logs-db` 优先使用事件自己的 thread_id，否则取从根到叶 span 中最后一个非空 ID；拼接 span 名、字段和事件正文，再排队写入。容量有限意味着缺日志不等于没执行。

读取数据库时校验 ID、JSON、时间和状态。线程时间低于 **1,577,836,800,000** 被视为旧秒精度并乘 1,000；这是兼容启发式，不是所有历史日期通用的时间解析器。时间规范化失败保留原值，未知 reasoning_effort 降为 None，但非法作业状态、负 max_runtime_seconds 或坏 JSON 返回错误。

## 边界与追溯

`SRC-0006/uc.sub/reconcile-thread-metadata` 优先保留数据库已有的三个 Git 字段，并比较 **22 个字段**定位变化。分页 anchor 的 UUID 无法解析时返回 None。系统时间早于 Unix epoch 的日志时间回退 0；打印时缺 thread_id 用 `-`，缺 message 用空串。日志 CLI 的路径选择、`CODEX_SQLITE_HOME`、彩色级别和 apply_patch diff 高亮仅影响查询/展示，不改变底层事件的成功与失败。
