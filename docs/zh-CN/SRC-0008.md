# SRC-0008：多智能体注册、派生与通信

> 本页是中文导读，不是 JSON 的逐字段译本。规则、结构和完整分支请以本模块原始数据为准。

原始数据：[规则](../../SRC-0008/rules.json) · [结构](../../SRC-0008/structural.json) · [用例](../../SRC-0008/use-case.json)

## 职责与关键实体

本模块是多智能体的控制面：创建与派生子线程、分配身份、应用角色配置、解析目标、传递邮件、恢复和关闭智能体树。`AgentRegistry` 管理活动树和计数；`AgentMetadata` 保存路径、昵称、角色和最近任务；`SpawnReservation` 以 RAII 方式持有尚未提交的名额；`AgentControl` 执行操作。`Mailbox` 与 `InterAgentCommunication` 将“收到消息”和“启动新轮次”分开。

入口：`SRC-0008/entity/agent-registry`、`SRC-0008/entity/spawn-reservation`、`SRC-0008/entity/agent-control`、`SRC-0008/entity/inter-agent-communication`。

## 主要规则

- `agent_max_threads` 有值时才限制子线程总数，根线程不占名额。达到深度上限的恢复线程会关闭 SpawnCsv 与 Collab；深度递增采用饱和加法。
- `agent_path` 必须唯一，预留占位也算占用。昵称池耗尽后增加轮次后缀，例如 `the 2nd`，并重置候选池。
- 派生保留 system、developer、user 消息，助手消息只保留 `FinalAnswer`；推理和工具调用等不继承。`LastNTurns(n)` 先裁剪再过滤，不能把“完整历史派生”理解为所有底层条目的原样复制。
- 自定义角色优先于同名内置角色。角色未明确指定 provider/profile 时尽量保留当前选择；空配置不重建配置。邮箱按 FIFO 投递，序号从 **1** 单调递增，只有带 `trigger_turn=true` 的待处理邮件要求启动轮次。

对应规则：`SRC-0008/rule/agent-max-threads-limit`、`SRC-0008/rule/root-thread-not-counted`、`SRC-0008/rule/fork-retain-filter`、`SRC-0008/rule/role-preservation-policy`、`SRC-0008/rule/mailbox-trigger-turn-detection`。

## 典型流程

创建子智能体先预留名额、路径和昵称，再创建线程、提交预留、记录父子边并发送初始任务。历史派生额外要求父调用 ID、派生模式和 ThreadSpawn 来源，并先物化、刷新父线程 rollout。恢复树通过数据库中状态为 Open 的父子边进行广度优先遍历；关闭则找到后代并依次关闭、移除注册和释放名额。按名字引用时先尝试线程 ID，否则相对当前智能体路径解析；列表可按子树过滤。

用例：`SRC-0008/uc.user/spawn-sub-agent`、`SRC-0008/uc.user/fork-agent-thread`、`SRC-0008/uc.user/resume-agent-tree`、`SRC-0008/uc.user/close-agent`、`SRC-0008/uc.sub/route-inter-agent-mail`。

## 边界与失败处理

`Interrupted` 不是终态，仍可继续；Completed、Errored、Shutdown、NotFound 才是终态。线程内部死亡会触发移除和名额释放。关闭已 Shutdown 的线程是幂等操作；遍历后代时忽略已不存在或已死亡线程，其他错误会中止剩余遍历。角色加载失败对调用方返回通用不可用消息，详细原因留在日志；未知角色则明确报错。旧式完成观察器受 MultiAgentV2 开关控制，不能假定所有模式都靠相同通知路径。

参见 `SRC-0008/rule/is-final-non-final-statuses`、`SRC-0008/rule/handle-internal-agent-died-cleanup`、`SRC-0008/rule/completion-watcher-feature-gated`。

身份继承也有条件：shell 快照仅从可用的 ThreadSpawn 父线程取得；执行策略还必须通过父子配置的继承判断。不能仅因存在父子关系就假设所有策略都相同。路径过滤按完整路径或斜杠分隔的子路径匹配，避免相似名字被误认为同一子树。
