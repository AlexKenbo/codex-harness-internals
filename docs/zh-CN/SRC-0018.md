# SRC-0018：执行运行时、Code Mode 与 JS REPL

> 本文是中文模块导读，不是逐字段译本。这里描述执行层，不把沙箱重试或审批路由当作绕过权限的操作建议。

## 职责与关键实体

本模块包含 `ApplyPatchRuntime`、`ShellRuntime`、`UnifiedExecRuntime`，以及 ZshFork 的 execve 拦截、策略决策与进程启动生命周期。另一组实体是 `CodeModeService`、`CoreTurnHost` 和嵌套工具分发器；再一组是 `JsReplManager`、Node kernel、`TopLevelExecState` 及双向 JSON 消息。它说明工具如何真正落到文件、进程或 JavaScript 运行环境，而不只是定义参数。

实体入口：[结构](../../SRC-0018/structural.json)，精确 ID：`SRC-0018/entity/shell-runtime`、`SRC-0018/entity/code-mode-service`、`SRC-0018/entity/js-repl-manager`。

## 主要规则与数值

- 补丁成功/失败退出码为 0/1；普通失败作为输出返回，识别为沙箱拒绝时才转换成 SandboxErr。shell 网络审批为 Immediate，UnifiedExec 为 Deferred。
- shell 快照包装仅在非 Windows、快照存在、cwd 匹配且命令为 `-lc` 等条件成立时发生。显式环境覆盖先捕获再恢复，`CODEX_THREAD_ID` 也保留；无效环境变量名忽略。
- Code Mode 显示 Yielded、Terminated、Result 状态，耗时四舍五入至 0.1 秒；按 token 预算分别裁剪纯文本或混合内容。Result 即使包含错误，也先更新 stored values。
- JS REPL 默认超时 30 000 ms，由 `Semaphore(1)` 限制单次顶层执行；杀进程后的等待最多 2 秒。stderr 尾部最多 20 行、每行 512 字节、总计 4 096 字节，UTF-8 安全截断。模型诊断中的错误和 stderr 又分别限制为 256、1 024 字节。

核对：[规则](../../SRC-0018/rules.json)中的 `SRC-0018/rule/shell-lc-snapshot-wrap-gates`、`SRC-0018/rule/code-mode-result-replace-stored-values`、`SRC-0018/rule/js-repl-stderr-tail-limits`。

## 用例流程

`SRC-0018/uc.sub/run-shell-command` 先处理 shell 快照和 PowerShell UTF-8 前缀，再选 ZshFork 或通用后端，构造沙箱命令和执行选项，启动并流式发送输出。ZshFork 按真实 execve 请求评估策略，选择 run/escalate/deny，审批等待时暂停计时器。

`SRC-0018/uc.sub/execute-js-repl` 获取执行锁、按需启动 Node，注册 exec ID 和响应通道，在写入前标记 Submitted，再等待结果并拆分文本/图片。Node 查找顺序为 `CODEX_JS_REPL_NODE_PATH`、配置路径、PATH 中的 node，还需通过版本校验。Code Mode 嵌套调用则构建隔离路由，按 Function/Freeform 选择对象/字符串 payload，再交给 ToolCallRuntime。详见[用例](../../SRC-0018/use-case.json)。

## 边界与失败处理

空命令、缺 argv[0]、启用 ZshFork 却缺 execve wrapper 都会拒绝；其他不满足 ZshFork 门槛的情况可回退。Code Mode 不可调用自身；未启用工具或 payload 类型错误直接报错。JS REPL 也禁止自调用，emitImage 仅接受 data URL。超时重置 kernel，写入失败或响应通道关闭按进程状态附加有界诊断；中断仅重置属于当前轮次的 FreshKernel/Submitted，不误伤 ReusedKernelPending。kernel 采用逐行 JSON 协议；清理同时处理待决调用、上下文和执行状态，避免把一次失败当作仍在运行。

## 阅读提示

这两个 JavaScript 执行通道的并发语义也不同：Code Mode 嵌套工具走运行时调度锁，而 JS REPL 直接分发嵌套调用，不通过同一并行调度锁。调试时必须先辨认调用来源，再解释为何某些工具能够重叠执行；不能把顶层单次执行锁理解为所有外部工具都串行。
