# SRC-0012：输出条目、图片产物、轮次差异与计时

> 本页是中文导读，不是 JSON 的逐字段译本。规则、结构和完整分支请以本模块原始数据为准。

原始数据：[规则](../../SRC-0012/rules.json) · [结构](../../SRC-0012/structural.json) · [用例](../../SRC-0012/use-case.json)

## 职责与关键实体

本模块把流式 `ResponseItem` 变成面向会话的 `TurnItem`，分派工具调用、保存非工具结果，并处理文件差异、图片落盘、首 token/首消息计时与轮次元数据。关键实体包括 `OutputItemResult`、`HandleOutputCtx`、`TurnDiffTracker`、`BaselineFileInfo`、`TurnTimingState` 和 `TurnMetadataState`，覆盖的不只是事件名称映射。

入口：`SRC-0012/entity/turn-item`、`SRC-0012/entity/turn-diff-tracker`、`SRC-0012/entity/turn-timing-state`。

## 主要规则

- 用户消息先识别可见 hook，再解析普通输入；与图片相邻的包装标签会去除。助手消息缺 ID 时生成 UUID v4，搜索缺 action 时使用 Other 和空查询。
- 图片产物保存为 `generated_images/<清理后的会话ID>/<清理后的调用ID>.png`；路径组件仅保留 ASCII 字母数字、`-`、`_`，其他字符替换为 `_`，空组件使用 `generated_image`。
- TTFT 表示首 token，符合条件的内容或工具调用可触发；TTFM 仅由助手消息触发。二者每轮只记录一次，重新开始轮次会重置；时间转换溢出饱和到 `i64::MAX`。
- 文件基线只在该轮首次 patch 时记录，统一差异每侧保留 **3 行**上下文；Git 模式分别为 `100644`、`100755`、`120000`。本地 blob OID 按 `SHA-1("blob {字节数}\0" + 数据)` 计算。

对应规则：`SRC-0012/rule/image-path-sanitization`、`SRC-0012/rule/ttft-ttfm-idempotency`、`SRC-0012/rule/diff-baseline-immutability`、`SRC-0012/rule/git-blob-sha1-formula`。

## 典型流程

完成的输出先交给 ToolRouter 判断：工具路径记录调用并创建带取消令牌的异步执行任务，标记需要后续轮次；非工具路径解析消息、推理、搜索或图片，清理隐藏标记及记忆引用，补齐开始与完成事件后记录历史。有效最终助手答案和图片生成会推迟邮箱交付，Commentary 不走该规则。

文件修改时保存初始内容和模式，重命名只更新路径映射；最终按仓库相对路径排序生成累计 diff。元数据后台并行获取 Git HEAD、远端和变更状态，优先使用增强 header，再合并客户端字段但不覆盖已有键。启用相应配置时，来自工具搜索或网页搜索的外部上下文会把线程记忆标为 polluted；有记忆引用且数据库可用时记录使用情况。

用例：`SRC-0012/uc.sub/handle-completed-output-item`、`SRC-0012/uc.sub/track-turn-diff-baseline`、`SRC-0012/uc.sub/enrich-turn-metadata-with-git`、`SRC-0012/uc.sub/record-completed-response-item`。

## 边界与失败处理

图片需先合法 base64 解码，再创建目录写文件，路径清理不是图片内容验证。文本不可解码时 diff 使用二进制差异提示；非 Unix 平台不按 Unix 方式识别可执行位和符号链接。没有 Git 仓库就不启动增强任务，同一元数据状态最多启动一次；JSON 合并失败保留原 header。上下文开发者消息可能混有持久文本，不能仅看到一个可裁剪片段就错误失效整个参考。输入到输出条目的转换只支持列明的四类工具输出，其余返回 None。

参见 `SRC-0012/rule/dev-message-contextuality-pairing`、`SRC-0012/rule/metadata-header-priority`、`SRC-0012/rule/response-input-to-response-item-coverage`。
