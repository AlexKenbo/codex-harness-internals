## 职责与关键实体

本模块管理模型可见历史、token 估算、上下文压缩、回滚、环境设置差异，以及全局用户输入历史文件。`ContextManager` 保存有序条目、用量、历史版本和 `reference_context_item`；`InitialContextInjection` 决定压缩后是否补入初始上下文；`CompactedItem` 保存摘要与替换历史；`EnvironmentContext` 与设置更新包表达环境和策略变化。

入口：`SRC-0011/entity/context-manager`、`SRC-0011/entity/initial-context-injection`、`SRC-0011/entity/settings-update-bundle`。

## 主要规则

- 内联压缩只保留最近用户消息，合计预算 **20 000 tokens**；边界消息按剩余预算截断，旧摘要不重复计入。工具输出记录采用基本截断策略的 **1.2 倍**序列化预算。
- 普通内联图片估作 **7373** 个模型可见字节；Original detail 使用 32px patch 估算。加密 reasoning/compaction 的估算有 base64 启发式及 **650** 的常量扣减，不能当成精确用量。
- 缺失工具输出会补入中止结果；孤立输出会移除，但 server 执行或无 call ID 的 ToolSearchOutput 有例外。幽灵快照保存在内部历史中，不发送给模型。
- 全局 `history.jsonl` 在 Unix 使用 `0600`；锁最多尝试 **10 次**，间隔 **100 ms**。超过硬容量后裁到约 **80%**软上限，但保留最新一行。

对应规则：`SRC-0011/rule/compact-user-message-token-budget`、`SRC-0011/rule/call-output-pairing-invariant`、`SRC-0011/rule/history-soft-cap`、`SRC-0011/rule/history-lock-retry-policy`。

## 典型流程

压缩根据提供方能力选择内联摘要或远程端点。内联生成摘要后组装近期用户消息；远程先裁剪允许移除的尾部，再过滤返回条目。两者都重新附加先前保存的幽灵快照，保证撤销所需信息仍在。轮次中压缩把初始上下文放到最后真实用户消息之前，并保存参考快照；手动或轮次前压缩清空参考，让下一轮完整重注入。

正常请求前还要补齐调用输出、移除孤立输出，并将不支持的图片替换为文本提示。上下文更新按模型指令、权限、协作模式、实时状态、个性顺序组成开发者消息，再补环境差异。记忆输入排除 AGENTS.md 和 skill 脚手架，但保留环境与子智能体通知。

用例：`SRC-0011/uc.sub/auto-compact-inline`、`SRC-0011/uc.sub/auto-compact-remote`、`SRC-0011/uc.sub/normalize-history-for-prompt`、`SRC-0011/uc.sub/build-settings-update-bundle`。

## 边界与失败处理

内联压缩仍可能超窗：有多个条目时删除最旧条目重试，只剩最小历史仍放不下则报错。远程预裁剪遇到用户或助手消息就停止，不跨越边界。远程返回的开发者消息会丢弃，不能由此推断 harness 此后不再重建必要指令。回滚同时清理轮次前的上下文更新，混合开发者文本需要使参考失效。历史持久化关闭时不写文件；容量未设置或为 0 时不强制裁剪。

参见 `SRC-0011/rule/context-window-exceeded-trim-policy`、`SRC-0011/rule/keep-compacted-history-item-matrix`、`SRC-0011/uc.sub/trim-pre-turn-context`。
