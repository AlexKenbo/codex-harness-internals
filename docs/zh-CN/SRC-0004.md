## 模块职责与实体

这一层定义动态工具的说明、请求和返回值，以及执行输出、MCP 资源、记忆引用、用户提问、权限申请和计划清单的数据结构。`UserInput` 支持文本、图片、本地图片、技能和提及；`TextElement` 与 `ByteRange` 将 UI 占位符绑定到原始文本位置，不需要修改用户字面内容。

## 主要规则

`SRC-0004/rule/max-user-input-text-chars` 将单个文本输入上限设为 **1,048,576 个字符**，不能把它当成 UTF-8 字节数。`ByteRange` 却是字节范围，start 含、end 不含；中文多字节字符和 emoji 的边界因此尤其重要。

动态工具延迟加载按 `deferLoading` → `!exposeToContext` → false 的优先级解析；新字段存在时优先于旧字段。工具返回内容标签为 `inputText`/`inputImage`，图片字段为 `imageUrl`，不能随意改成 snake_case。MCP 的部分字段接受 camelCase 与兼容别名，`meta` 在 wire 上写作 `_meta`。

权限申请只允许 network/file_system 字段，默认授权范围为 **Turn**，不是 Session。计划项状态仅 pending、in_progress、completed；计划结构同样拒绝未知字段。问答响应以 question ID 为键，不能用题目显示顺序代替 ID。

## 主要流程

`SRC-0004/uc.sub/decode-shell-stream-bytes`：空输入直接给空串，合法 UTF-8 走快速路径；否则检测旧编码。只有检测为 IBM866、含允许的 Windows-1252 智能标点且相邻 ASCII 单词满足限制时，才改用 WINDOWS_1252。若有 ≥ 0xA0 的字节、非法标点或缺少 ASCII 字母，就不做该修正；最终解码报错才用有损 UTF-8 替换。

`SRC-0004/uc.sub/serialize-local-image-to-data-url` 在序列化请求时读取本地图片，将路径转换成带 base64 data URL 的 Image。`SRC-0004/uc.sub/track-text-element-spans` 在文本合并或迁移时重映射字节范围，但保留 placeholder；调用方仍须保证范围对应原逻辑元素。

## 边界与追溯

`Resource.size` 的宽松 i64 转换保留能表示的整数，过大无符号数或不适合的值变 None，不拖垮整个资源。旧客户端缺失 turn_id 时得到空串，缺失文本元素得到空列表；提问的 isOther/isSecret 默认 false。`UserInput` 标为 non_exhaustive，消费者应为新增变体留分支。请求 ID 可为字符串或 i64，但不能将二者混为同一个键。工具输出的默认退出码 0 只是构造默认值，不能作为实际执行成功的证据。
