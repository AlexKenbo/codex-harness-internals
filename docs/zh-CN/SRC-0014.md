# SRC-0014：工具路由、调度与执行生命周期

> 本文是中文模块导读，不是逐字段译本。实现细节描述的是仓库中的规范快照。

## 职责与关键实体

本模块把模型响应里的调用转成可执行的 `ToolCall`，借助 `ToolRouter`、`ToolRegistry` 找到 `ToolHandler`，在 `ToolInvocation` 中携带会话、轮次和追踪上下文，再将不同工具输出封装成 `AnyToolResult`。`ToolCallRuntime` 控制并发与取消，`ToolOrchestrator` 负责审批、沙箱选择和符合策略的重试，`ToolEmitter` 统一 shell、补丁、UnifiedExec 的开始与结束事件。输出既能面向模型，也能转换为 Code Mode JSON、日志预览和 hook 数据。

实体入口：[结构](../../SRC-0014/structural.json)，精确 ID：`SRC-0014/entity/tool-router`、`SRC-0014/entity/tool-call-runtime`、`SRC-0014/entity/tool-orchestrator`。

## 主要规则与数值

- 每次 dispatch 将工具调用计数饱和加 1。允许并行的调用持读锁，顺序调用持写锁；默认规格不允许并行。MCP 的并发能力按服务器名判断。
- 有修改行为的处理器先等待 `tool_call_gate`。PreToolUse 可以阻止执行；PostToolUse 只在成功时运行，反馈或停止结果可替换工具回复。
- 遥测预览同时受 2 KiB 和 64 行限制，截断标记为 `[... telemetry preview truncated ...]`；这是日志预览限制，不是所有工具完整输出的统一上限。
- 命令耗时显示到 0.1 秒，取消时至少显示 0.1 秒；MCP 结果头保留四位小数。非零命令退出码转为面向模型的错误；补丁退出码 0 为 Completed，其余为 Failed。

核对：[规则](../../SRC-0014/rules.json)中的 `SRC-0014/rule/parallel-execution-rw-lock`、`SRC-0014/rule/telemetry-preview-size-limit`、`SRC-0014/rule/post-tool-use-hook-only-on-success`。

## 用例流程

`SRC-0014/uc.sub/dispatch-tool-call` 的路径为：计数 → 查找处理器 → 检查 payload 类型 → 前置 hook → 等待修改门闩 → 执行 → 收集日志 → 成功后置 hook → 兼容旧 AfterToolUse hook。响应路由同时处理 Function、Custom、MCP、LocalShell 和客户端 ToolSearch；LocalShell 缺 call_id 时可回退到 id。审批编排先判断要求，选择初始沙箱，再执行；只有工具及审批策略允许时，沙箱拒绝才可进入经授权的重试路径。详见[用例](../../SRC-0014/use-case.json)中的 `SRC-0014/uc.sub/run-tool-with-approval-and-sandbox`。

## 边界与失败处理

找不到工具返回 unsupported call；类型不兼容是 Fatal。旧 AfterToolUse 的 FailedAbort 终止操作，FailedContinue 仅记录警告。`js_repl_tools_only` 阻止除 REPL/reset 外的直接调用；不可用历史工具可获得占位规格和说明。用户拒绝、审批超时与网络策略拒绝保持不同原因，不能视作自动无沙箱重试许可。取消返回专门输出；超时命令附加超时文本。纯文本单项可压平，混合内容保留条目；空文本/图片 URL 在 Code Mode 转换时过滤，补丁的 Code Mode 结果固定为 `{}`。

## 阅读提示

排查一次调用时，建议依次确认响应条目是否被识别、名称与负载是否匹配、前置钩子是否放行、修改门闩是否就绪，再看审批及真正执行的结果。日志预览可能截断，不能据此断言原始输出缺失；输出被后置钩子替换，也不代表底层工具没有执行。
