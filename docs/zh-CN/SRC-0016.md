# SRC-0016：具体工具处理器与参数校验

> 本文是中文模块导读，不是逐字段译本。它连接工具规格与运行时，不应将某条工具规则推广为全部工具的行为。

## 职责与关键实体

本模块覆盖补丁、动态客户端工具、JS REPL、目录列表、MCP 调用与资源、计划、权限/输入请求、shell、同步测试、工具搜索/建议、UnifiedExec 和图片查看的处理器。`ToolInvocation` 提供统一上下文，具体参数类型各自验证；`EffectiveAdditionalPermissions` 合并会话与轮次授权，`ToolSearchIndex` 用 BM25 检索可用工具。与 SRC-0018 的底层运行时相比，这里重点是入口校验、请求组装和返回协议。

实体入口：[结构](../../SRC-0016/structural.json)，精确 ID：`SRC-0016/entity/tool-handler-registry`、`SRC-0016/entity/effective-additional-permissions`、`SRC-0016/entity/tool-search-index`。

## 主要规则与数值

- `list_dir` 的 offset、limit、depth 均至少为 1，目录必须是绝对路径；条目最多 500 字节且在 UTF-8 边界截断，缩进每层 2 个空格，目录/符号链接分别带 `/`、`@`。
- UnifiedExec 默认 `tty=false`、`yield_time_ms=10_000`；WriteStdin 参数默认等待 250 ms。测试同步屏障默认超时 1 000 ms，参与者与超时都必须为正。
- 工具搜索拒绝空 query 或非正 limit。未显式指定 limit 且首轮结果涉及 `computer-use` 时，扩展检索到 20；之后仍按服务器限制结果数量。
- 附加权限必须匹配 `with_additional_permissions`，无预批准时受功能开关和 OnRequest 策略约束。只有有效权限完全落在既有 grants 内才标记预批准，不能把部分覆盖当作全部批准。
- `request_user_input` 只允许根线程并受模式限制；`update_plan` 在该快照的 Plan 模式中禁用。MCP 资源分页 cursor 必须与 server 一起使用。

核对：[规则](../../SRC-0016/rules.json)中的 `SRC-0016/rule/list-dir-arg-validation`、`SRC-0016/rule/tool-search-computer-use-expansion`、`SRC-0016/rule/preapproval-intersection-check`。

## 用例流程

补丁路径 `SRC-0016/uc.sub/apply-patch-to-files` 为解析输入 → 获取执行环境 → 验证补丁 → 收集目标及移动路径 → 合并权限 → 仅为不可写目标的父目录生成额外写权限 → 直接返回或委派编排器。shell/exec 还会拦截 apply_patch，避免走错管线。动态工具则注册响应通道、发给客户端并等待结果。工具安装建议在用户接受后还要刷新并核对实际安装/可访问状态。详见[用例](../../SRC-0016/use-case.json)。

## 边界与失败处理

缺环境时补丁、shell、UnifiedExec 不可用；补丁正确性错误、无法解析、非补丁输入有不同分支。JS REPL 拒绝空输入、Markdown 围栏和 JSON 包装，pragma 仅支持一次 `timeout_ms`。动态响应通道关闭返回取消错误。UnifiedExec 在早期拒绝或成功拦截补丁后释放已分配的 process_id，避免泄漏；TTY 跳过后置工具 hook。图片查看要求模型支持图像输入、路径确为文件，`detail` 仅接受 `original` 或省略，不支持原图时回退缩放。历史工具缺失返回明确的 unavailable 提示，而非假装执行成功。

## 阅读提示

排障时先区分参数解析失败与实际执行失败：前者可能尚未触及外部状态。目录分页越界、空资源名称和不允许的登录 shell 都在入口被拦下；安装建议则可能已经产生外部动作，因此完成标志需要额外查询核实，不能仅依据确认界面的返回值。
