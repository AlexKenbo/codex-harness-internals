# SRC-0007：会话记录、索引与归档

> 本页是中文导读，不是 JSON 的逐字段译本。规则、结构和完整分支请以本模块原始数据为准。

原始数据：[规则](../../SRC-0007/rules.json) · [结构](../../SRC-0007/structural.json) · [用例](../../SRC-0007/use-case.json)

## 职责与关键实体

本模块覆盖 rollout 持久化、线程列表与分页、会话恢复、SQLite 元数据修复与历史回填，以及归档和名称查找。`RolloutRecorder` 将写入请求交给后台 `RolloutWriterState`；`RolloutItem` 包含 `SessionMeta`、`ResponseItem`、`Compacted`、`TurnContext` 和 `EventMsg`。`ThreadItem` 是列表摘要，`Cursor` 用于分页，数据库中的线程元数据不是完整对话的替代品。

精确入口：`SRC-0007/entity/rollout-recorder`、`SRC-0007/entity/rollout-writer-state`、`SRC-0007/entity/thread-item`。

## 主要规则

- 文件名为 `rollout-YYYY-MM-DDThh-mm-ss-<uuid>.jsonl`；活动记录按日期分目录，归档记录平铺。列表条目必须同时找到 `SessionMeta` 和用户消息事件，第一次出现的 `SessionMeta` 决定线程身份。
- 每次扫描最多 **10 000** 个文件；游标格式为 `<ts_rfc3339>|<uuid>`，按时间和 UUID 降序稳定分页。文件修改时间截到毫秒，旧式时间格式也有解析回退。
- 写入通道容量为 **256**。`Limited` 与 `Extended` 决定事件保存范围；`ItemCompleted` 仅保留 Plan 类型。扩展模式的命令聚合输出截到 **10 000 字节**，并清空重复的 stdout、stderr 和格式化输出。
- 回填租约为 **900 秒**，每批 **200** 个文件，批后记录 watermark；名称索引从文件尾按 **8192 字节**块反向扫描，同一线程以最新名字为准。

对应规则：`SRC-0007/rule/listing-scan-cap`、`SRC-0007/rule/event-msg-persistence-matrix`、`SRC-0007/rule/exec-aggregated-output-truncation`、`SRC-0007/rule/backfill-lease`、`SRC-0007/rule/session-index-latest-per-id`。

## 典型流程

记录条目先过滤、清理，再入队；后台按需创建文件，写元数据和待写条目，随后同步数据库。恢复会话先尝试数据库列表，必要时退回文件扫描；cwd 匹配依次检查缓存、最近的 `TurnContext`、会话元数据。归档先校验真实路径和文件名，再重命名；恢复归档则重建日期目录并更新修改时间。回填扫描活动与归档目录，排序、续接 watermark，再逐批更新数据库。

用例入口：`SRC-0007/uc.sub/record-rollout-items`、`SRC-0007/uc.user/resume-session`、`SRC-0007/uc.user/archive-thread`、`SRC-0007/uc.user/unarchive-thread`、`SRC-0007/uc.sub/backfill-sessions`。

## 边界与失败处理

写入失败会关闭句柄并重开重试 **一次**；尚未成功写入的条目仍留在缓冲区，相同错误日志去重。归档要求规范化后的路径位于指定目录内，且文件名匹配线程 ID，防止越界移动。恢复读取可跳过损坏 JSON 行并记录错误；空历史视为新会话，非空但找不到线程 ID 则失败。数据库归档标记属于尽力更新，不能把数据库更新失败误判为文件从未移动。

参见 `SRC-0007/rule/writer-recovery-retry-once`、`SRC-0007/rule/archive-path-scoping`、`SRC-0007/rule/filename-thread-id-match`。

名称查找不是简单地搜索任意历史命中：它从尾部扫描并对线程 ID 去重，旧名字不会重新成为当前名字。如果最新候选的 rollout 不可读，会继续寻找其他同名且已持久化的会话。数据库回填的成功、失败与部分失败有独立统计，单个文件失败不应被包装成整个索引完全成功。
